# Emporio da Musica — AI Customer Service Agent

A grounded AI customer service agent for a Brazilian musical instruments retailer. The project combines structured data tools, store-policy retrieval, and an optional local large language model to answer customer questions.

## Project Overview

The agent assists customers with questions about musical instruments, product availability, prices, promotions, orders, and store policies.

Its main goals are to:
- Provide accurate answers grounded in the store's data.
- Use structured tools for product and order queries.
- Retrieve relevant information from the store policy document.
- Handle questions outside the store's scope appropriately.
- Offer a local LLM integration while retaining a deterministic fallback.

## Features

- Product catalogue search using CSV data.
- Product price and stock lookups.
- Category and promotion queries.
- Order status and tracking information.
- Store-policy retrieval from a PDF document.
- Streamlit chat interface.
- Command-line interface.
- Optional local LLM integration through Ollama.
- Automated tests with pytest.

## Architecture

The application is organized into the following components:

- `app.py`: Streamlit user interface.
- `main.py`: Command-line entry point.
- `src/agent.py`: Deterministic agent and fallback behavior.
- `src/ollama_agent.py`: Local LLM integration and tool-calling orchestration.
- `src/data_tools.py`: Structured access to catalogue, inventory, promotions, and order data.
- `src/knowledge.py`: Retrieval of relevant passages from the store policy PDF.
- `data/`: CSV datasets and the store policy document.
- `tests/`: Automated tests.
- `examples/`: Verified conversation examples.

The application uses structured data tools for factual business information rather than relying on the language model to invent product or order details.

## Installation

Clone the repository:

```bash
git clone https://github.com/MhrzDev/emporio-ai-agent.git
cd emporio-ai-agent
```

Create and activate a virtual environment.

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the project and development dependencies:

```powershell
python -m pip install --upgrade pip
pip install -e ".[dev]"
```

## Configuration

Copy the example environment file:

```powershell
Copy-Item .env.example .env
```

The application supports these environment variables:

- `USE_LLM`: enables or disables local LLM mode.
- `OLLAMA_BASE_URL`: Ollama API base URL.
- `OLLAMA_MODEL`: model name used by Ollama.

For local LLM mode, install and start Ollama, then download the model:

```powershell
ollama pull qwen2.5:7b
```

Set the environment variables in PowerShell:

```powershell
$env:USE_LLM="true"
$env:OLLAMA_BASE_URL="http://localhost:11434"
$env:OLLAMA_MODEL="qwen2.5:7b"
```

The deterministic mode can be used without enabling the local LLM.

## Running the Application

## Data and Knowledge Retrieval

The project uses CSV files for products, categories, customers, orders, order items, and promotions.

Product and order information is accessed through structured data functions. Store-policy information is retrieved from `data/store_policies.pdf`.

The current policy retrieval implementation uses keyword-based matching. It is not a vector database or embedding-based semantic search system.

Customer contact details and order tracking values in the public demonstration datasets have been replaced with synthetic demonstration values. The dataset structure and relationships are retained.

## Design Decisions

- **Grounded responses:** factual product, stock, price, and order information comes from the store datasets.
- **Tool-based access:** business data is accessed through explicit functions instead of being generated by the model.
- **Local LLM option:** Ollama allows the model to run locally without requiring a hosted model API key.
- **Deterministic fallback:** the application can operate without the LLM integration.
- **Policy retrieval:** the policy PDF provides the source material for customer-service policy answers.

## Limitations

- Policy retrieval is keyword-based and may not identify every relevant passage when a question uses substantially different wording.
- The local LLM's response quality depends on the selected model and available hardware.
- The demonstration datasets are static and do not connect to a live inventory, payment, shipping, or e-commerce platform.
- Order information reflects the supplied sample data, not real-time order systems.
- The application is a technical demonstration and is not intended for production use without further security, monitoring, and operational work.
